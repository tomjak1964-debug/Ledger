# App development standards (v1.0, 2026-11-05)

How every app in `~/src` is built, so menus, documents, lists, forms and actions look and behave the same
everywhere. Written from a read-only survey of Ledger, Golf League, MMMO, HOA Manager, Resale Shop, GateA and
Wedding Planner plus the HomeServer app template (`App Standards Survey.md` has the evidence, file by file).

**Status:** v1.0, agreed by Tom on 2026-11-05 (all eight decisions below as proposed). It is to live in HomeServer
`templates/app/STANDARDS.md`, be copied into each app as `docs/STANDARDS.md`, and the reference code it names is to be
copied into `templates/app` (HomeServer session).

## Decisions (Tom, 2026-11-05)
1. **Deleting:** an ordinary delete has an Undo toast and no question; a confirm only for what can't be undone (S4.6).
2. **Sorting:** click any column heading, everywhere; no "Sort:" dropdowns (S3.2).
3. **Printing:** always through a PDF, never printing the app page (S2.3).
4. **Rows:** tapping a list row opens the record, in every app including Ledger (S3.4).
5. **Updates:** office apps install updates themselves when safe; Golf and MMMO keep an Update button (S1.3).
6. **Permissions:** fail closed: anything not explicitly granted is hidden (S5.4).
7. **Button wording:** sentence case everywhere ("Add contact", "Save"); Ledger's Title Case changes gradually (S4.5).
8. **Golf / MMMO:** keep their dark, tabbed phone look as an allowed variant (S1.1).

## How to use this (for Claude sessions)

- **Before building or changing** a menu, page header, document/report, list, form, button, dialog, toast, upload,
  phone/email display, permission or Excel feature, read the matching section here and **use the reference code**
  (copy it from `templates/app`, or from the app named, if it isn't in your app yet). Don't invent a new way.
- If the standard doesn't fit, **ask Tom** before doing it differently, and say so in the PR.
- When you touch an area of an existing app that doesn't meet the standard, bring that area up to it in the same PR
  (or list it in the PR as a follow-up). Don't rewrite unrelated areas without asking.
- Every PR says "Standards: followed" or names the exception.
- Rule ids (S1.2 …) are for referring to rules in PRs and conversation.

Applies fully to the **office apps** (Ledger, HOA, Resale, Wedding, new apps). The **phone-first event apps**
(Golf League, MMMO) keep their tab strip, dark theme, code+PIN sign-in and "update by button", and follow
everything else. GateA (one static page) follows S2 (documents), S5.1 (call links) and S8 (formatting) where it can.

## S1. Shell and look

**S1.1 Menu.** One `NAV` list (groups → `{k, label, icon}`), a `TITLES` entry (title + subtitle) per page, a
`NAV_AREA` entry per page, one line per page in the view switch. Navy grouped sidebar; picking a page folds it on
wide screens (`.menu-tab` brings it back); `← Back` in the top bar; ≤900 px a drawer with scrim, closed by Escape.
Remember the current page in `sessionStorage` so a reload or self-update returns to it. `aria-label="Menu"` on the
menu button, `aria-current="page"` on the active item. Every menu item has its **own** icon.
*Reference:* Wedding `App.jsx` + shell CSS; page memory from Resale `App.jsx`.
*Variant:* Golf/MMMO tab strip (`role="tab"`, `aria-selected`).

**S1.2 Page header.** `.topbar`: menu button, `<h1>` title + `.sub` subtitle from `TITLES` (fallback
`TITLES[k] || [k, ""]`, never crash), then `.topbar-actions` in this order: **Search → Refresh → Back**.

**S1.3 Revision and updates.** `app/version.json` "Rev X.yy" (bump yy for every visible change, X for a big one;
"(Rev X.yy)" at the end of PR titles). Template `lib/version.js` + `components/RevisionFoot.jsx` unchanged:
`Rev X.yy · ✓ Up to date`, self-installs when `safeToUpdate()`. Also shown under the sign-in card. Apps that must not
reload mid-use set `AUTO_UPDATE = false` (Golf, MMMO) and get the "Update to Rev X" button only. Always "Rev", never "v".
**Anything being edited carries `data-editing`** (see S4.8).

**S1.4 Sign-in and passwords.** Template sign-in with the centred brand block (Wedding). Every password field is a
`PasswordInput` with Show/Hide (Ledger/Resale). "Forgot password" only when the app can send email; otherwise say
"Ask an admin for a new password". Change password = the template's `ChangePassword` modal from the menu foot. Menu foot
order: name · role, then email + Sign out, then Change password. Minimum password length 10.

**S1.5 Branding.** Source `logo-vN.svg`, small cut `favicon-vN.svg`, print logo `logo-print-vN.svg` (no background),
PNGs 64/192/512 + maskable + apple-touch 180 generated by a script (`gen-icons.mjs`), `BrandMark` = `<img>` of the SVG.
Icon file names carry a version; bump it when the icon changes. `viewport-fit=cover`, `theme-color` = `--ink`.
*Reference:* Wedding `public/` + `ui.jsx BrandMark`; Ledger `gen-icons.mjs`.

**S1.6 Tokens and classes.** Colours, radii and shadows only as the template's `:root` tokens (`--ink --canvas
--surface --line --accent --muted --pos --warn --neg …`). An app changes values and may **add** tokens (Wedding's
`--gold`, `--serif`); never renames them; no hard-coded colours in components. Base classes only: `.card .card-body
.btn(.primary .ghost .icon .sm .danger) .link-btn .field .input .badge .modal .overlay .empty .toast .toolbar`.
**Phone inputs are 16 px** (`@media (max-width:640px){input.input,select.input,textarea.input{font-size:16px}}`) so iOS
doesn't zoom on focus. Date inputs get Ledger's iOS CSS (`appearance:none`, min-height, left-aligned).

**S1.7 Icons.** One `ICONS` map (24×24 stroke paths, `Ico` with `aria-hidden="true"`) in `components/icons.js`.
Fixed meanings:

| Action | Key | Action | Key |
|---|---|---|---|
| Add | `plus` | Close | `x` |
| Edit | `edit` (pencil) | Back | `back` (chevron) |
| Delete | `trash` | Call | `phone` |
| Print | `print` | Text | `chat` |
| Export / Save file | `download` (tray) | Email | `mail` (square) |
| Import / Upload | `upload` | Settings | `settings` |
| Search | `search` | Sign out | `logout` |
| More actions | `more` (⋯) | Attachment | `clip` |

Apps add domain icons (`cake`, `cart`) but never reuse an action key for something else. **No emoji as UI icons**
(emoji as content, e.g. GateA categories, are fine). Toolbar buttons are icon + label; icon-only buttons (rows,
compact toolbars) use `IconButton({icon, label})`, which sets both `title` and `aria-label`. Tap targets ≥ 36 px.

**S1.8 Loading and errors.** Boot "Starting up…" → "Loading…". A failed load shows "Couldn't load … " + **Try again**
(Ledger). An `ErrorBoundary` around the page switch (Resale). Phone apps used outdoors show a stale/offline bar (MMMO).

## S2. Documents, reports and printing

**S2.1 Opening a document.** Every document and report opens as a portalled full-screen `.doc-screen` overlay
(grey desk, white Letter-width page, sticky dark toolbar respecting safe areas). Escape or Close closes it.
Reports keep the open report in the address (`?report=key`).
*Reference:* Wedding `components/ReportDoc.jsx` (`ReportScreen`); Ledger `DocumentView` for transactional documents
(make it portal).

**S2.2 Document toolbar.** Ledger `DocActions`, always this order:
**Close** (back icon) · [document options] · **Edit** · **Email** · **Save ▾** (PDF / Excel / Word, each showing its
file name) · **Print** (primary, right). A button appears only if the document supports it. While a file is being
made the button says "Preparing…" and is disabled. Labels stay on phones; the bar wraps.

**S2.3 Print = make the PDF, then print the PDF.** Never `window.print()` of the app page (keep print CSS only as a
Ctrl+P safety net). Print builds the PDF, shows it in `PdfView` (iframe; the printer dialog opens by itself) with
Save PDF; paper, saved file and emailed file are identical.
- **Table reports:** vector PDF from the report's own tables, Ledger `lib/reportPdf.js` (selectable text,
  headings repeat on every page, rows never split, >8 columns landscape). Rebrand from tokens + print logo.
- **Designed documents** (letters, cards, charts, proposals, multi-column sheets): picture PDF, Wedding
  `lib/pdf.js` `elementToPdf` (laid out at computer width on any device, one canvas per page, cuts between rows
  and paragraphs never after a heading, `.pdf-break` forces a page, page numbers + running header).
- Letter paper (cards 5 × 7). Never A4.

**S2.4 iPhone / iPad.** `isIOS()` (incl. iPad reporting as Mac) → make the PDF → small dialog "*file* (n pages) is
ready" with **Save PDF** and primary **Print…** → `navigator.share({files})` (Share sheet: Print, Save to Files, Mail,
AirDrop); ignore AbortError; no Share sheet → open the PDF. One `IOSPrintHost` in App reached via
`printOrShare(build)`, event `app:share-print`.
*Reference:* Ledger `lib/printSupport.js` + `components/IOSPrintHost.jsx`, with Wedding's page count and error text.

**S2.5 File names.** `docFileName(parts, ext)`: Title Case title, then the filter/party, then an ISO date
(`Guest List - Invited 2026-11-05.pdf`); unsafe characters removed, colons → " - ". Transactional documents use their
number (`INV-0042.pdf`). `document.title` = the same stem while open. Excel/Word use the same stem.

**S2.6 Page furniture.** Page 1: letterhead (print logo, organisation, title in the brand serif, subtitle =
range/as-of/filter, "Prepared <date>"). Later pages: running line "Org · Title · filter" top right. Every page:
footer org · "Printed <date>" · **Page n of m**. Table column headings repeat on every page.

**S2.7 Choosing reports.** A grid of cards (icon, title, one-line description), shown only if the person can read
its area; grouped under category headings when there are more than ~8. Filters in Ledger's `FilterBar` (date presets
with **Year to Date** default, Custom, party pickers, Summary/Detail, Clear). The active filter appears in the
report heading and on every PDF page.

**S2.8 Report tables on phones.** Every report table is a `ReportTable` that writes `data-label`; under 640 px each
row becomes a stacked card of label: value pairs (Wedding `styles.css` `.rtable`). Wide ledger-style tables may
scroll sideways as a named exception. The PDF is always laid out at computer width.

**S2.9 Email.** An Email button in `DocActions` opens Ledger's `EmailModal`, attaching the **same** PDF Save and Print
make; sends through a server function (Resend), logs every send. Until an app has email, the iPhone Share sheet covers it.

## S3. Lists

**S3.1 One `DataTable`.** Every list of records uses the template `DataTable` (from Resale `components/DataTable.jsx`
+ `lib/exporters.js`): one column spec `{key, label, get, type: money|num|pct|date, phone:"hide"}` drives the screen,
Excel and PDF.

**S3.2 Sorting.** Every visible column sorts by its heading (`useTableSort` + `SortTh` rendering a `<button>` with
`aria-sort`); an `initialSort` is required. Exempt: line-item editors, dashboards, running balances, tick lists whose
rows must not move. Grouped lists keep group header rows inside the sorted table.

**S3.3 Toolbar.** One `.toolbar` above the table: **search** (`type="search"`, placeholder names the fields, always
shown) → **quick filters** (segmented control with counts, e.g. "All 213 · Past due 4", HOA `.seg`) → other filters
(selects / `FilterBar`) → `.toolbar-end`: Export, Import, then the **primary Add button last**. Filters set from a
Dashboard link arrive via `go(view, {filter})`. Search clears when you leave the page.

**S3.4 Rows.** Tapping a row opens the record (rows are focusable, open on Enter). At most one labelled primary row
action (`btn sm`, e.g. "Payment") and up to two `IconButton`s; everything else in the portalled `⋯ ActionMenu`
(Ledger `ui.jsx`). Controls inside a row stop the click from opening it.

**S3.5 Cards or list.** A table for things people compare (money, dates, status); cards for people and places you act
on (call, text, map). Where both fit, a **Cards | List** toggle remembered in `localStorage` `<page>-view` (Wedding Contacts).

**S3.6 Selection.** A **Select** button turns on select mode: checkbox column, select-all over the filtered rows,
sticky bar "N selected (· $total)" with the actions and Cancel (Ledger Invoices). Destructive bulk actions get Undo.

**S3.7 Empty states.** `<Empty icon title action>` with three states: Loading…; **none yet** (what the page is for +
the Add button if the person can write); **none match** ("37 households are hidden by the search or filters" + Clear
filters).

**S3.8 Phones.** Under 640 px `DataTable` rows stack as labelled cards; columns can be hidden with `phone:"hide"`.
Tables that must stay wide use `.tbl-wrap{overflow-x:auto;overflow-y:hidden}` (and `.card` gets `overflow-y:hidden`
too: it stops iOS trapping vertical swipes).

**S3.9 Large tables.** Load growable tables through `fetchAll(build)` (Resale `lib/store.js`): every stack caps a
response at 1000 rows and silently drops the rest. `DataTable` shows 500 then "Show all N rows".

**S3.10 Counts and badges.** Menu badges come only from `counts` in `App.jsx` and count things needing action
(overdue, to review). One status vocabulary: grey draft, blue open, green done, amber waiting, red overdue (Ledger `Badge`).

**S3.11 Excel export.** `.xlsx` via ExcelJS (lazy-loaded, Wedding `lib/excel.js`). Exports **exactly what's on
screen**: sorted, filtered rows and visible columns, plus totals; money and dates as real numbers/dates with formats;
navy header, frozen, autofilter; the active filters in the sheet title. Name `"<List> YYYY-MM-DD.xlsx"`. CSV only where
another system needs it, with a UTF-8 BOM.

**S3.12 Import.** One modal (carrying `data-editing`): explanation + **Blank template** → choose .xlsx/.csv → headers
matched by alias list + `normHeader`; an unmatched required column gets a "match the column" select (Resale) → a
**preview of the plan**, each row New / Update / Skipped (reason) / Possible duplicate, with counts (Wedding
`GuestImport`) → rows with an exported ID update that record; duplicates skipped unless "import anyway" → write in
batches → toast "Imported: N new, N updated, N skipped".

**S3.13 Global search.** Once an app has 3+ record types: a top-bar box, Ctrl/Cmd+K, searches only readable areas,
≤12 results labelled by kind, arrow keys + Enter, **opens the record itself** (`go(view, {open:id})`).

## S4. Forms, editing and actions

**S4.1 Where things are edited.** A **modal** for a record of up to ~15 fields (Resale `Modal`); a **full page**
(with `data-editing`) for documents and multi-part editors; **in-place cells** only for grids of numbers and checklists.

**S4.2 Fields.** `Field({label, hint, required})` whose `<label>` is tied to its control (wraps it or uses `useId`),
hint under the field, examples in placeholders as "e.g. …", required marked `*`, labels in sentence case.
Inputs: money `type="text" inputMode="decimal"` (accepts $ and commas, parsed with `parseMoney`, shown in tabular
figures; not `type="number"`); dates `type="date"` (optional ones get Clear); phones `type="tel" autoComplete="tel"`;
emails `type="email"`.

**S4.3 Validation.** Check in `save()`; show the first problem inline as `<p className="error" role="alert">` just
above the modal foot, worded as an instruction ("Enter a name."), and focus that field. Turn known database errors
into sentences. Toasts only for errors outside a form.

**S4.4 Saving.** Records: an explicit Save, disabled while saving ("Saving…"), lit only when something changed.
Grids of numbers and checklists save per change (on blur/tick) with a one-line hint saying so (Wedding `NumberBox`).
Autosave that fails shows a "not saved — Retry" bar (Golf). "Save & add another" where people enter many in a row.

**S4.5 Buttons.** Modal foot: **[Delete]** (danger, at the left, only for an existing record the person can write) …
**Cancel** · **primary** (far right). Primary label: "Save" when editing, "Add <thing>" when creating. Sentence case
everywhere. Danger buttons are outlined; filled red only inside a confirm dialog.

**S4.6 Deleting, confirm and Undo.**
- Deleting one record that can be put back: **no confirm, an Undo toast** (`toast("Deleted Florist", {actionLabel:"Undo", onAction})`).
- Destructive things that can't be undone (removing a login, deleting with children, clearing data, voiding, bulk):
  a **confirm dialog** naming the record and the consequence, through the shared `confirmDialog({title, body,
  confirmLabel, danger})` (a `Modal`, returns a Promise). No `window.confirm`, `prompt()` or `alert()` in new code.

**S4.7 Toasts.** Resale's toast: `toast(msg, {actionLabel, onAction, ms, error})` and `fail(e)`; errors red with ✕;
`role="status"`; a newer toast is never cut short by an older timer; sits above the iPhone home bar
(`bottom: calc(22px + env(safe-area-inset-bottom))`). Wording: past tense naming the thing ("Saved Jane Doe"), no
exclamation marks; errors say what happened and what to do. 2.6 s, 8 s with Undo, 6–10 s for errors.

**S4.8 Keyboard, unsaved changes, updates.** Modal and editor bodies are a `<form onSubmit={save}>` (Enter saves;
other buttons `type="button"`). Escape closes the topmost modal. `Modal` has `role="dialog" aria-modal="true"
aria-labelledby`, a labelled ✕, focuses the first field, and takes a `dirty` prop: when dirty a backdrop tap is
ignored and ✕/Escape asks "Discard your changes?". Full-page editors ask on Back. The same `dirty` flag sets
`data-editing`, so a self-update never lands under unsaved work.

**S4.9 Read-only.** Hide create and delete controls; read-only people can still open a record to view it, inside
`<fieldset disabled>`, titled with the record's name, foot = Close. Toggles show disabled rather than hidden. RLS
in the database is what enforces access; the UI only mirrors it.

## S5. Shared building blocks

**S5.1 Phones, email, contacts.** Every phone number is a `PhoneLink` (`tel:`; extensions written `x12` dial after a
pause), every email an `EmailLink` (`mailto:`), every address a map link. A person or business record has
`ContactButtons` (Call / Text / Email). Save to phone = vCard through `saveFile` (S5.3).
*Reference:* Wedding `lib/contact.js` + `components/CallLinks.jsx`.

**S5.2 Files and photos.** Private buckets, opened through signed URLs (1 h for display, short for downloads); open the
new tab **first**, then point it at the URL (iPhone blocks a `window.open` after an `await`). Photos shrunk in the
browser to 2400 px JPEG (the stacks don't resize), HEIC converted where the browser can decode it. Size cap 50 MB;
`ACCEPT` list; if the database row fails, remove the stored file. Record name, MIME, size and uploader.
*Reference:* Wedding `lib/files.js` + Resale `shrinkImage`; UI Ledger `components/Attachments.jsx` with thumbnails.

**S5.3 Saving files.** One `saveFile(blob, name)`: Share sheet first when `navigator.canShare({files})` (iPhone
home-screen apps), else `<a download>`. Used for PDF, Excel, CSV and vCards.

**S5.4 Access.** Roles owner / admin / member / viewer. Per area: No Access / Read / Read/Write / Approver
(`none|read|write|approve`; Approver only where an area has decisions). **Fails closed:** an area missing from a
member's permissions is `none`, a page missing from `NAV_AREA` is hidden (only an explicit `null` = everyone);
viewers capped at read. Database: template `001_members.sql` + `can_approve`, owner protection (`members_guard`),
keep-an-admin (`keep_an_admin`). RLS on every table via `can_read/can_write/can_approve(area)`.

**S5.5 People & Access page.** Add person with quick setups, people without a login (Create login later), Generate
password (no look-alike characters) + handover card (Wedding); per-area radio matrix with `aria-label`s and "set all
to" (HOA); email invite once the app sends email. One server function `admin-users` (create / update /
reset-password / delete / invite); only an owner can touch an owner; never remove the last admin.

**S5.6 Supabase.** Template client plus Ledger's fetch wrapper (30 s timeout, one retry: fixes the first save after a
phone wakes). Client-made ids and idempotent upserts. Numbered migrations `app/supabase/migrations/NNN_name.sql`,
applied by hand (backup → `--single-transaction` → `notify pgrst`), listed in CLAUDE.md. `security definer` helpers
with `set search_path`. Server functions in `app/supabase/functions/<name>/`, using the caller's JWT so RLS applies;
the service key only for auth admin, never in the app. Deploying a function needs Tom's OK.

**S5.7 Settings and dashboards.** An admin Settings page: one card per topic, each with its own Save lit when
changed (tabs past ~5 cards). Dashboard tiles are real buttons (HOA `Tile`), shown only for readable areas, linking
with a filter; a "Needs attention" list.

**S5.8 Email.** Resend, only from a server function; recipients resolved on the server; one log row per recipient
with status, written only by the function, read-only to members; "Send me a test".

**S5.9 History.** Every table has `created_at`, `updated_at`, `updated_by`. Optional template `audit_log` filled by a
trigger, read-only to clients.

## S6. Code and docs

**S6.1 Formatting.** One `lib/helpers.js` (from Resale): `money(n,{cents})`, `moneyAcct`, `parseMoney`, `fmtDate`,
`fmtDateTime`, `fmtTime`, `fmtMonth`, `todayISO`, `addDays`, `daysBetween`. Date-only strings are never parsed with
`new Date("YYYY-MM-DD")` (UTC): use local noon. Money in Postgres `numeric(12,2)`; dates `date`; times `timestamptz`.

**S6.2 Files.** `src/views` pages only; `src/components` reusable UI; `src/lib` plain JS; `src/calc` pure rules with
tests. Standard names: `lib/permissions.js helpers.js files.js contact.js excel.js pdf.js printSupport.js
supabaseClient.js version.js`, `components/ui.jsx icons.js DataTable.jsx ReportDoc.jsx DocActions.jsx PdfView.jsx
CallLinks.jsx RevisionFoot.jsx ChangePassword.jsx`. `NAV_AREA` (not on NAV items); `AREAS` items use `key`.
SQL snake_case, JS camelCase, statuses stored as lowercase keys with labels in JS. Double quotes.

**S6.3 CLAUDE.md skeleton** (≤ ~300 lines; history and long domain notes in `docs/*.md`): What this is · Where it
runs · House rules · Backend · Database changes (applied list) · Access model · Logins · Features (dated decisions) ·
Lists, Excel and reports · Standards (pointer to `docs/STANDARDS.md`, exceptions) · Still to come.

**S6.4 Changing the standard.** When an app does something better, propose it to Tom; if agreed, change
`templates/app` and this file together, bump the version at the top, note it in the changelog below, and sync the
copies. Apps adopt it when that area is next touched.
